# BHYH 全面代码质量审计

> 触发本 skill 后：对 BHYH 项目执行一次全面、可复核的代码质量审计，复制 `docs/audit/AUDIT-000-audit-template.md` 后填写 `docs/audit/AUDIT-XXX-code-quality-audit-<日期>.md`。**本报告第 8 章是唯一状态源**，第 0 章看板、结论与修复路线图必须与之对应。
>
> **只读审计**：不修改源码、ADR、既有文档或历史报告。仅允许新增本次审计报告、生成导入/验证缓存及隔离的验证产物；修复另开迭代。

## 背景（必读）

- 工程边界与红线：`AGENTS.md`（§1 项目边界、§2 核心架构、§4 命名、§6 提交、§7 验证、§8 文档维护）
- 架构与遗留边界：`docs/reference/architecture.md`
- 验收标准与门禁：`docs/reference/acceptance.md`
- 当前状态与已知边界：`docs/reference/status.md`
- 规范：`docs/standards/` 全部活跃文档（命名、Godot 设计、白名单、缺失资产、SpriteFrames）
- 决策记录：`docs/decisions/` 全部 ADR（决策合规维度按模板 3.10 核对表逐条执行）
- 路线图：`docs/roadmap/roadmap.md` + `docs/roadmap/current-iteration.md`
- 工具链：`scripts/README.md`
- 审计档案：`docs/audit/README.md`、`docs/audit/AUDIT-000-audit-template.md`

## 审计范围

- 实现范围：`source/**/*.gd`、`source/**/*.tscn`、`source/**/*.gdshader`、`source/**/*.json`、`source/project.godot`、`source/**/*.tres` 与相关 `.import` / `.uid` 的当前实际清单。文件数量、模块职责和热点按本轮统计，不沿用历史报告结论。
- 资源范围：`source/Art/**/manifest.json`、图集页、SpriteFrames/AtlasMetadata/Spine 资源的引用、导入与构建期产物；不评价美术质量。
- 验证范围：`scripts/` 的门禁、回归、双人探针与转换器作为验证契约；`scripts/coop_probes/` 是可执行规格，不进入生产源码。
- 只读契约/接线输入：现行 docs、ADR、`project.godot`、`scripts/` 可用于核对实现契约、门禁与目录边界；不扩展为第三方实现或素材质量审计。当前契约描述错误登记 `DOC`，环境失败单列验证限制。
- 第三方边界：`source/addons/`、`source/bin/` 的内部实现不审、不改；只核对集成边界、版本、资源路径与许可证。`source/.godot/` 导入缓存不审。
- 公开仓库边界：`source/Art/`、`Music/`、`Font/`、`Spritesheet/` 可能缺失；缺失资源提示不自动构成缺陷。完整审计以本地合法授权的完整素材工作区为准，并记录实际覆盖范围。

启动前记录提交、用户既有改动与实际文件清单；报告说明逐文件覆盖、切片负责人、未审部分和统计方法。按实际能力使用 codegraph（仅 Python）、Context7、LSP、godot-mcp；GDScript 引用检索用 `grep`/`read`/`LSP`。工具未挂载/索引不可用时先记录再按项目规则降级，截断清单和不完整引用不能证明全覆盖或没有调用者。可独立分片只读审查，门禁及运行验证由主审统一执行。

## 执行方法（按序）

1. **基线与平台门禁**（记录到模板 4.1）：
   - 记录 `git rev-parse HEAD`、`git status --porcelain` 与实际工作树快照；不清理用户既有改动。
   - 以 `docs/reference/acceptance.md` 为准选择档位：L0 静态门禁、L1 引擎健康、L2 运行期夹具、L3 发布收口。全面审计默认至少 L0 + L1；涉及玩法/关卡/双人/HUD/资源时追加 L2。
   - 先运行 `python scripts/check_all.py --skip-engine`，记录 7 维结果与契约 WARNING 预算。
   - 有 Godot 4.7.2 时运行 `python scripts/check_all.py --godot-bin <godot>` 与 `python scripts/health_check.py --project source --godot-bin <godot>`；引擎路径只使用 `<godot>` / `--godot-bin` / `GODOT_BIN` 占位，不记录本地绝对路径。
   - 新增/重命名资源时执行 `godot --headless --path source --import`；它只证明导入缓存重建，不等于构建、运行或门禁通过。
   - 运行期按范围选择 `level_test_runner.py`（代表关）、`level_regression_all.py --changed-only --diff-base <base>` 或全量回归、`coop_probe_runner.py`（涉及 LocalCoop）、三个转换器 `--check` / `--self-test`。
   - 禁用 `check_all.py --fix`、逐文件例行检查、用 shell 通配替代完整清单。结果按实际填写通过/失败/未执行/受限；命令 exit 0 不等于零警告、完整覆盖或消费者契约已验证；任一失败先定位记录，不在审计中修复。
   - 门禁会生成 `docs/reports/` 机器报告与 `.godot/` 缓存；审计只引用结论，不提交机器报告。删除本次新增的临时产物前先记录基线，不删除用户既有文件。
2. **全部 ADR 合规核对**（模板 3.10）：
   - 枚举 `docs/decisions/` 实际 ADR 并与索引核对，记录有效/废止/被替代及继承关系；以 `docs/decisions/README.md` 的实际索引为准，不固定编号上限或表行数。
   - 每条先分离当前有效决策本体、当前事实描述和历史事实，再填写实现消费者、可执行检查、API 前提及未覆盖范围。有效决策用合规/部分合规/违反；证据不足用未验证，废止且本轮无适用规则用不适用，不冒充合规或违反。
   - 仅已确认的有效决策违反/部分合规登记 `CMPL`；事实描述错误按只读纪律登记 `DOC`，历史差异不自动成为问题。
   - 重点核对：ADR-003 设计规范、ADR-004 命名、ADR-005 无回退/跨版本迁移链、ADR-006 Resource 优先、ADR-007 Autoload 边界、ADR-009 构建期资产、ADR-012 门禁、ADR-013 路径迁移、ADR-017 双人隔离。旧实现残留检查针对旧路径、旧 API、双加载分支和消费者调用；裸词 grep 零命中不能单独证明合规。
3. **分领域审查**（模板 3.1~3.10）：保留 10 个领域，逐项给评级（A~D）、本轮结论与关联问题；既审模块，也追踪跨边界状态转换，如场景切换→释放旧场景、加载页→关卡、暂停→双人面板、保存线程→退出、资源预热→关卡释放。必须有可达消费者和反例，不凭类型、命名或历史结论预判缺陷。
4. **验证、证据与统计**：
   - 按实际填写 4.1 的平台、配置、完整命令、工作目录、退出码、覆盖及证据；不可用/受限项说明原因。4.2 分开统计业务脚本/插件脚本、场景、资源、实际执行的关卡/探针/转换器，不引用旧数字。
   - 验证程度与处理状态/优先级独立：运行确认、静态确认、推断待证。正式问题需运行反例或可复核的可达消费者/契约违反证据；仅推断候选留在第 8 章待证区，不计正式问题，不因未运行危险场景降低已确认风险级别。
   - 每个证据使用报告内稳定 `EVID-NNN`，按 4.4 保留基线/环境、前置条件、最小输入或代码、精确命令或可复建配方、预期、实际输出和未验证范围。路径/版本可参数化，但必须说明取值与依赖；不能用 `...` 或将被删除的临时路径代替配方。
   - **验证隔离**：运行前确认不会覆盖真实 `user://` 存档、设置和日志；使用可丢弃工作区/副本，必要时先备份。`level_test_runner` 的临时驱动/报告/日志在 `source/` 生成后自动清理；审计不得把真实用户数据用于破坏性实验。无法安全隔离的项目标记受限，继续其余可达工作。
   - 先核实探针走生产工厂、真实资源路径、槽位路由和 API 前提，再归因项目缺陷；探针自身编译/前置错误单列，不算产品反例。headless、离屏、单机或人造争用只证明所列范围，不能外推为桌面、双人、真实音频/硬件或 Android/Steam Deck 已验证。
   - 清理临时程序/产物前将最小复现和关键输出嵌入报告，或引用明确可持久读取的证据；仅会话产物不作唯一依据。主审统一执行消费者冒烟，不新增永久测试或审计平台。
5. **问题总表与历史 ID**（模板第 8 章）：
   - 本轮新问题按 12 个领域前缀分别从 001 连续编号，完整身份为 `AUDIT-XXX:<PREFIX>-NNN`，报告内可简写；`EVID-NNN` 仅是本报告证据 ID，不参与问题编号。
   - 相同根因不因路径/表现不同重复登记；不同根因不因现象相同就合并。对照 `docs/reference/status.md` 已知边界、`docs/standards/missing_assets_registry.md` 与历史报告：新反证重开保留原报告+原 ID，列原结论、新可达证据和重开原因，不回写旧报告。
   - 仅复核已有问题放第 8 章已知项复核区：有原 ID 保留来源命名空间，无原 ID 用文档路径+原标题锚+基线引用，不以长标题冒充本轮新编号；同项不能同时在正表和复核区计数。
   - 正式表区分新发现/历史重开/已知复核、验证程度、处理状态和证据/复审引用；纯推断另放待证区。第 0 章分别统计来源，再对已确认唯一项按优先级/状态汇总，不混入待证候选或重复引用。
6. **排期与交付自检**：
   - 保留 P0~P3 路线图：未处理/处理中列处理项，已缓解/已暂缓列复审时间与重开条件，已关闭不纳入未闭环集合。
   - 从第 8 章正式表与已知复核区提取全部非已关闭的完整 ID/来源锚，与第 5 章完整引用去重排序后用可复核集合比较（Python/comm 等）核对；实际记录缺失/多余及重复数，不能只检查本轮新编号。
   - 核对 0~8 章、10 个领域、12 个前缀、动态覆盖、报告引用、直接验证证据、原失败保留、隔离产物清理及源码/既有文档未越界修改；不创建新的审计平台。

## 纪律（硬性）

- **只读边界**：仅写本次新报告和隔离验证产物，不修源码、ADR、既有文档或历史报告，不执行自动修复、自动提交或破坏性缓存清理。审计前记录基线与用户既有改动，交付时核对越界变更；清理自有临时产物，不删除用户文件。
- **验证隔离**：执行门禁和探针前确认配置、日志与输出不会覆盖真实 `user://` 存档、设置或用户目录；无法安全隔离的项目标记受限，继续其余可达工作，不以全量测试通过掩盖跳过项。崩溃、OOM、慢插件强杀等实验只允许在可丢弃且有限制的环境中执行。
- **ADR 两类处理**：当前事实/契约描述被证伪 → 登记 `DOC` 并引用原文，另开迭代修订，不开 `CMPL`；实现违反当前有效决策本体 → 登记 `CMPL`。历史上成立、后来被取代的事实保留背景，不因不同于当前实现就改写原文或登记违例。
- **P0/P1 从严**：启动/场景切换崩溃、存档损坏或丢失、核心战斗/关卡不可继续、死循环/长时间阻塞、敏感数据泄露 → P0~P1，不因“暂未触发”降级。
- **不夸大**：静态确认与运行确认分别记录；未观测的退出、性能、资源/硬件影响标 `[未验证]`，纯推断标 `[推断]` 并列明待证条件。测试数量、exit 0、一次不崩溃不能单独证明消费者契约或用于关闭已确认缺陷。
- **复审与文档分工**：原始发现证据保留，可在本次报告第 8 章更新状态并补充验证程度/证据/复审引用，不堆修复过程。第 7 章只追加复审记录，修复详情写实现迭代与 roadmap；已固化历史报告不改写，新的审计/复审使用接续报告并保留原问题身份。
- **公共仓库与平台**：缺失第三方素材不自动记为缺陷；Spine 仅 Windows x86_64、Steam Deck/Android 未完整验证等边界必须写入未验证范围。
- **提交纪律**：审计默认不提交；用户明确要求提交时，按 `AGENTS.md` §6 使用 docs 类型、单逻辑单提交，且未经允许不得 `git push`。

## 交付

- `docs/audit/AUDIT-XXX-code-quality-audit-<日期>.md`（完整报告 0~8 章，序号接续已有报告）
- 实际门禁结果、覆盖/环境限制（4.1~4.3）；原失败、替代验证与单独补跑不相互覆盖
- 持久可复核的消费者证据（4.4）与尚未运行的桌面/双人/平台手工清单（4.5），明确前置条件及安全隔离
- 关键发现和建议下一步按第 8 章与路线图一致交付；明确说明本次只读、未修改源码/ADR/既有文档、未提交
