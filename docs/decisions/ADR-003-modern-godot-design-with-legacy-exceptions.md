# ADR-003：新代码遵循 Godot 现代设计规范，遗留结构登记例外

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：场景设计、依赖注入、Resource、Autoload、重构边界

## 背景

当前工程包含 Flash 正位重构留下的大型全局状态、类型分层目录与深层节点路径。一次性重写风险过高，但继续按旧模式扩张会让新代码与规范进一步分叉。

## 决策

1. 新代码与主动重构代码遵循 [`godot_design_standard.md`](../standards/godot_design_standard.md)：
   - 场景单一职责、自包含、可复用；
   - 外部依赖优先 `@export` 或父上下文注入；
   - 场景内部优先 `%UniqueName` + `@onready`；
   - 子节点通过 `signal` 通知父级；
   - 新结构化数据优先 `Resource` / `.tres`；
   - 新代码禁止跨场景深层 `get_node()` 与 `/root/...` 绝对路径；
2. 现有遗留结构登记为“遗留例外”，保留但不继续扩张；
3. 大规模迁移必须单独立项，不混入普通功能提交；
4. 新增 Autoload、输入动作、物理层或全局资源路径必须说明生命周期与验证方式。

## 后果

- 新代码有明确可执行的规范，旧代码不会因“历史原因”被要求立即重写；
- 代码库会在一段时间内保持“新规范 + 旧例外”并存；
- 评审需要识别改动属于新代码、主动重构还是遗留扩张；
- 遗留债务必须逐步下降，不能以例外为由新增同类结构。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 立即全量重写为功能优先架构 | 风险、回归面与工作量不可控，破坏已验收行为 |
| 冻结所有旧结构，不写新规范 | 新代码继续复制旧模式，债务持续增长 |
| 只做文档规范，不接入门禁 | 规范无法阻止回归 |
