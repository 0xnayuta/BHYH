# ADR-015：文档分层，`status.md` 为状态单一事实源

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：文档结构、报告、归档、状态更新

## 背景

项目文档曾包含大量阶段报告、逐文件迁移台账与旧路径映射。它们会迅速过期，并与当前规范/状态冲突。需要明确哪类信息放在哪里、哪些内容可以长期保留。

## 决策

1. 文档按职责分层：
   - `docs/reference/`：当前状态、架构、验收、项目范围；
   - `docs/roadmap/`：路线图与当前迭代；
   - `docs/guides/`：操作方法与迁移手册；
   - `docs/standards/`：活跃规范；
   - `docs/reports/`：脚本生成的机器报告；
   - `docs/archive/`：已完成且仍有长期参考价值的文档；
   - `docs/decisions/`：架构决策记录（ADR）。
2. [`status.md`](../reference/status.md) 是版本、规模、门禁与验证结果的**单一事实源**；
3. `reports/` 由脚本按需生成，不提交历史报告，不手工编辑；
4. `archive/` 归档后原则上只读，不接收机器报告、临时台账与旧路径映射；
5. 文档不得记录本地私有二进制路径、解密沙盒、密钥或绝对路径；
6. 新增/移动文档必须同步索引与相对链接；归档必须登记到 `archive/README.md`；
7. 规范变更顺序：先改 `docs/standards/`，再改代码/门禁，最后重新生成报告。

## 后果

- 当前事实、计划、规范、历史与机器报告边界清晰；
- `status.md` 需要持续维护，否则会成为过期单点；
- 阶段报告不再入库，追溯依赖归档与提交记录；
- 文档链接成为验收的一部分。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 所有文档平铺 | 无法区分当前事实、规范与历史 |
| 把报告提交进仓库 | 噪声大、迅速过期、与脚本输出冲突 |
| 用 Wiki 代替仓库文档 | 与代码版本不同步，无法随提交审查 |
