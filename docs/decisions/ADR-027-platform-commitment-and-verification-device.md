# ADR-027：平台承诺与验收设备边界

- **状态**：Accepted
- **记录日期**：2026-11-08
- **影响范围**：平台矩阵、发布验证、性能验收、文档术语
- **关联**：ADR-001、ADR-002、ADR-016、ADR-020、Phase 21/26

## 背景

项目当前只能在 Windows x86_64 桌面端开发与验证，且无法确认“最低 Windows 配置”等硬件下限。
此前 Phase 26 使用“目标设备性能”表述，容易被误读为已存在确定的目标硬件基线；实际数据来自
验证机（AMD Radeon RX 6750 XT、Vulkan 1.4.315、Forward Mobile、`max_fps=150`），
不能代表未声明的低端 Windows、Android 或 Web。

## 决策

1. **唯一承诺平台**：Windows x86_64 桌面。项目长期仅在该平台进行开发与验证，不承诺其他平台。
2. **最低硬件配置不声明**：不虚构最低 Windows 配置；当前验收设备固定为验证机，并记录
   机器型号、GPU/驱动、渲染后端、分辨率与 `max_fps`。
3. **其他平台**：Linux、macOS、Android、Web、iOS 保持“延期、未验证、不承诺”；不补运行库、
   不写支持声明；`.gdextension` 路径声明不等于运行库已入库。
4. **术语**：Phase 26 的“目标设备性能”统一改称“**验证机性能基线**”；性能结论只做
   同机前后对照与波动范围，不跨设备承诺。
5. **证据元数据**：性能证据必须附带机器、驱动、渲染后端、分辨率、`max_fps`、日期与
   未验证范围；缺少这些元数据不得作为验收结论。
6. **变更入口**：若未来需要最低配置或其他平台，必须新增 ADR 定义硬件基线/设备矩阵，
   不得沿用本机数据；release 导出与 PCK 验证仍按 `acceptance.md` 单独执行。

## 后果

- Phase 26 可以在“Windows x64 + 验证机”口径下推进 26-0/26-1/26-2/26-3，不再等待未定义的最低设备；
- 性能优化（如加载链路、法宝预热）可以立即进行，但验收只能声明“本机同参数改善”，
  不能声明目标设备达标；
- 文档中的“目标设备”若指未验证硬件，必须改写为“最低配置/其他平台”；
- 未支持平台有明确原因，不因本决策新增兼容承诺。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 虚构最低 Windows 配置并按其验收 | 没有设备与数据来源，违反“失败/未知显式”原则 |
| 等待取得多平台设备后再启动 Phase 26 | 长期阻塞，且与当前仅 Windows 开发的决策冲突 |
| 沿用“目标设备”表述 | 会把验证机数据误读为最低配置结论 |
