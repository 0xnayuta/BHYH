# ADR-016：1280×800 画布、1600×1000 窗口与桌面 HUD 基线

- **状态**：Accepted
- **记录日期**：2026-10-25
- **决策生效**：Phase 12（2026-10-23 / 2026-10-24）
- **影响范围**：显示、相机、HUD、多分辨率、移动端

## 背景

旧配置使用 `viewport 1200×400` 与 `window 1504×944`，实际可见逻辑高度约 753，底部露出默认清屏色。HUD 硬编码坐标、双人布局缺失、超宽屏右侧灰边等问题需要统一基线。

## 决策

1. 设计画布 **1280×800（16:10）**；
2. 默认窗口 **1600×1000**，与画布精确 **1.25×**；
3. 拉伸模式保持 `canvas_items` + `expand`，不切换到 `viewport`（避免先渲染到 1280×800 再放大）；
4. 相机缩放 **1.2**，世界可视约 1067×667，并按窗口高度计算纵向偏移，保留原屏幕下边缘；
5. 桌面 HUD：
   - 底部居中 5 按钮（宠物、技能、法宝、背包、设置），54×54、间距 5、底边距 4；
   - 左下无双圆盘与 Y/U/I/O/L 技能槽；
   - 双人 P2 镜像贴右，按键标签使用小键盘 3/4/5/6/8；
6. 移动端保留右上角/触控布局，不把桌面布局强加给手机；
7. 小屏设备按可用屏幕进入全屏，不强开 1600×1000 窗口；
8. 多分辨率验收覆盖 16:10、16:9、21:9，超宽屏用背景镜像覆盖，不拉伸世界。

## 后果

- 16:10 构图稳定，16:9 通过 `expand` 增加横向可视区域；
- HUD 使用锚点/容器与统一常量，减少单分辨率硬编码；
- 相机缩放与纵向偏移需要逐关验证边界、Boss 镜头与特殊关卡；
- 21:9 静态背景可能存在镜像接缝，需要美术资源层面优化；
- Steam Deck 全屏与 Android 实机仍需单独验证。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 保持 1200×400 / 1504×944 | 底部清屏色、逻辑高度不一致 |
| `viewport` 拉伸 | 降低有效渲染分辨率，高分屏发虚 |
| 窗口固定 1280×800 | 与设计画布相同，失去 1.25× 清晰度收益 |
| 全平台统一桌面 HUD | 移动端触控布局与安全区不同 |
