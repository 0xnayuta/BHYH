# ADR-001：仓库只保留一个活跃 Godot 工程

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：仓库结构、构建入口、发布与验收

## 背景

工程由 Flash 历史版本反编译基线迁移而来，历史上存在多个版本目录、参考工程与解包产物。若同时保留多个可运行工程，会出现主场景、Autoload、资源 UID 与门禁目标不一致的问题。

## 决策

1. `source/` 是唯一活跃 Godot 工程，`source/project.godot` 是唯一工程配置；
2. 业务代码、场景、资源改动只进入 `source/`；
3. `docs/` 只保存文档，`scripts/` 只保存工具链，二者不包含可运行工程；
4. 历史版本、反编译参考工程、解包沙盒留在仓库外，不作为构建目标；
5. 已完成阶段的资料进入 `docs/archive/`，归档后只读，不重新成为活跃工程。

## 后果

- 构建、门禁、关卡回归只有一个目标目录，路径与报告口径统一；
- 公开仓库是代码、场景与工具链快照，不包含第三方素材；
- 旧版本不能被直接运行或作为对照工程提交，版本差异必须通过迁移流程消化；
- 新增“演示工程”“临时工程”属于架构变更，必须单独评审。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 每个版本保留独立工程目录 | 资源 UID、Autoload 与门禁目标分裂，维护成本高 |
| 保留一个 `legacy/` 可运行工程作参考 | 参考工程会再次成为事实标准，阻碍治理 |
| 把工程拆分到多个仓库 | 当前规模与协作方式不需要，反而增加同步成本 |
