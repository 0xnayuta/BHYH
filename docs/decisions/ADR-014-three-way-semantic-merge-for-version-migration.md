# ADR-014：版本迁移使用三方语义合并，禁止整包覆盖

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：版本迁移、脚本/场景/资产合并、验收

## 背景

新版本来自反编译/解包参考工程，包含上游行为变化，但不包含当前工程的命名、类型、契约与架构治理。整包覆盖会丢失治理成果；机械 diff/patch 会把旧命名与旧结构重新引入。

## 决策

1. 始终使用三方语义合并：
   - `base`：目标版本之前的反编译源码基线；
   - `ours`：当前 `source/` 治理后的工程；
   - `theirs`：新版本参考反编译源码；
2. 禁止新版本整包覆盖当前工程；
3. 禁止把反编译 diff 直接 patch 到治理后的源码；
4. 每个功能域单独移植、单独验证、单独提交；
5. 新文件按当前架构重写，不直接复制反编译文本；
6. 不复制 `.ctex`、旧 `.import`、`.remap`、`uid_cache.bin`、旧导入缓存或上游 `Test/`；
7. 侵入性系统（如双人模式）最后接入，先建接口再改基类；
8. 上游测试探针只作为可执行规格，在仓库外或 `scripts/coop_probes/` 中等价重写。

## 后果

- 保留当前工程的命名、类型、契约与现代化模块；
- 迁移速度较慢，需要维护三方基线与逐文件映射；
- 每个批次必须可编译、可运行、可回滚；
- 参考工程与二进制留在仓库外，文档不得记录本地路径或密钥。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 新版本整包覆盖 | 丢失治理成果，重新引入旧命名/旧结构 |
| 直接应用反编译 diff | 冲突与噪声大，无法保证语义 |
| 只移植“公告提到的文件” | 公告不是实现证明，容易漏基线修复 |
