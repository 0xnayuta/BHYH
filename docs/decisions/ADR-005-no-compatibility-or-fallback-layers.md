# ADR-005：不保留兼容层、回退层与跨版本迁移链

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：资源加载、清单解析、存档、配置、路径解析

## 背景

迁移过程中曾同时存在“Manifest 清单”和“旧硬编码路径表”、“构建期 SpriteFrames”和“运行时建帧”、“新路径”和“文件不存在就回退旧路径”等双轨逻辑。双轨会隐藏数据错误、扩大测试面，并让旧行为永久存活。

## 决策

1. 同一资源/数据只能有一个正式来源；
2. 不新增以下逻辑：
   - 清单缺失时回退旧路径；
   - 文件不存在时尝试另一套命名；
   - 新旧两套加载路径并存；
   - 为兼容旧资产保留的双分支；
3. 清单缺失、路径缺失、类型不符必须明确失败（`push_error` / `assert` / 返回失败），不得静默降级；
4. 已登记在 [`missing_assets_registry.md`](../standards/missing_assets_registry.md) 的缺失资产回退属于历史遗留例外，不作为新增回退的依据；资源恢复后应移除对应回退；
5. 存档只保证**当前格式内**的容错：
   - 稳定密钥与 `.bak` 备份恢复；
   - `ensure_*` 补全缺失字段与清理退役数据；
   - 有限、幂等的字段规范化（如道具存储迁移）；
   - 不建立按版本号递增的通用迁移链；
6. 旧 `user://` 存档目录、旧任务键与旧配置不迁移；不可读/非法档明确失败。

## 后果

- 运行时路径更短、行为更可预测，错误更早暴露；
- 旧数据需要一次性清理或在外部工具中转换，不能依赖运行时猜测；
- 删除回退分支时必须同步迁移所有调用点，禁止保留“暂时兼容”的旁路；
- 合法例外仅限明确的容错读取与默认值补全，且必须在文档中写明边界。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 永久保留兼容层 | 双轨逻辑长期存在，无法证明哪条路径真正生效 |
| 用“文件是否存在”自动选择路径 | 掩盖命名错误，跨平台行为不一致 |
| 每次版本升级都写迁移脚本并保留旧分支 | 分支累积，测试矩阵爆炸 |
