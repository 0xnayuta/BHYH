# ADR-020：类型化视觉资产、显式后端与流式生命周期

- **状态**：Accepted
- **记录日期**：2026-10-26
- **替代**：[ADR-009](ADR-009-build-time-visual-asset-pipeline.md)
- **关联**：ADR-005、ADR-006、ADR-010、ADR-015、ADR-018

## 背景

FrameSequence 已接入生产，但旧契约混淆帧数与内存预算、元数据与纹理预热、正常资源选择与失败回退。线程加载请求在消费者退出后仍可能持有结果，字符串路径也不自动构成导出依赖。用户批准先修订契约，再收口现有实现。

## 决策

1. 保留构建层、资源层、运行时层；统一契约，不统一所有播放器。
2. 普通逐帧内容优先 SpriteFrames；时间轴编排允许原生 AnimationPlayer/AnimationTree；现有 Spine 内容遵守 ADR-010，新增骨骼内容允许原生 Skeleton2D。
3. 流式方案按目标平台驻留量、并发、首帧延迟与加载峰值选择，不以有限/超大帧数作为唯一标准。
4. 固定视觉数据离线构建，运行时只读；存档、当前格式用户数据和程序化内容不在固定资产禁令内。
5. 后端显式选择；声明资源失败不能换来源。构建期和运行时边界均校验，release 失败行为不能仅依赖 assert。
6. 线程请求有所有者并去重；消费者退出后的结果必须被取回释放，不能同步阻塞退出；预热保持纹理引用直到交接或释放。
7. 延迟加载路径必须形成单独发布依赖清单；不得以强引用全部纹理破坏 streaming。导出包需验证实际依赖闭包。
8. 共享资产数据只读，实例播放状态分离；资产身份不编码浮点播放策略。现有策略复合 key 的切换必须一次性迁移消费者，不保留旧 key 兼容。
9. 构建工具具备内容、schema、UID、依赖闭包检查；仅首帧显示不能作为完整验收。
10. 规范不保存迁移计数或当前完成状态；实际架构、验证快照与路线图各司其职。

## 后果

StreamedPngEffect 不再因类名被视为永久遗留；消费构建资源且满足生命周期契约的使用属于正式方案。允许受控异步加载与状态轮询，不允许恢复目录扫描或失败回退。原生骨骼能力不被 Spine 项目边界禁止。

## 备选方案

- 所有内容转 SpriteFrames：破坏骨骼能力和按需驻留，不采用。
- 万能播放器/全局资源平台：增加耦合，无实际需要不引入。
- 只依赖 assert 与首帧探针：不能覆盖 release、退出与导出，不采用。
