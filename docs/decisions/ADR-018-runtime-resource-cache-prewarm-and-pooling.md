# ADR-018：运行期缓存、分阶段预热与对象池

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：加载、帧率、显存、战斗特效、音频

## 背景

战斗场景会在短时间内加载角色、怪物、技能特效、法宝、宠物与命中资源。现场 `load()`、重复实例化伤害数字/音效播放器会造成卡顿、GC 抖动与显存峰值。加载页已经承担预载职责，需要明确缓存、预热与回收契约。

## 决策

1. 加载页负责分阶段预热：
   - 目标场景 → 角色运行时清单 → 角色专属特效 → 剑阵 → 法宝 → 战斗命中资源 → 宠物 → 关卡怪物；
2. `Global` 维护四类缓存：`_resource_cache`、`_sprite_frames_cache`、`_audio_cache`、`_texture_cache`；
3. 线程化预载，移动端并发槽位 2、桌面 4；进度封顶 90%，完成后再进入切换阶段；
4. 关卡资源按轨迹精确失效，战斗缓存按前缀清理；退出存档会话时释放对应资源；
5. 伤害数字、受击特效、角色受击、音效播放器使用对象池，容量 80 / 32 / 24 / 32；
6. 战斗加载输出 `[Battle VRAM]` 日志，记录加载阶段显存增量；
7. 不在 `_process` / `_physics_process` 中执行磁盘 IO、运行时 JSON 解析或高频 `load()`；
8. 预热资源必须有明确所有者与释放路径。

## 后果

- 战斗进入更平滑，减少首次技能/特效卡顿；
- 内存与显存占用上升，需要按关卡释放；
- 缓存键与失效轨迹必须准确，否则会残留或误释放；
- 新增资源类型需要接入对应的缓存分类与预热清单。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 全部按需加载 | 战斗卡顿、显存峰值不可控 |
| 全局无上限缓存 | 长时间游玩内存持续增长 |
| 每个场景重建全部资源 | 加载时间与 GC 压力过大 |
