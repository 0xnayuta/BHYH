# ADR-019：测试探针与夹具不进入生产源码

- **状态**：Accepted
- **记录日期**：2026-10-25
- **影响范围**：测试、回归、发布包、源码清洁度

## 背景

版本迁移与功能修复会产生临时探针、驱动场景、逐文件台账与上游 `Test/` 资源。如果直接放入 `source/`，会污染生产工程、增加导出体积，并可能被误当作业务代码维护。

## 决策

1. 可长期复用的测试规格放在 `scripts/`：
   - `scripts/coop_probes/`：双人探针矩阵；
   - `scripts/level_test_runner.py`：单关冒烟夹具；
   - `scripts/level_regression_all.py`：批量回归；
2. 夹具在运行时临时复制/生成到 `source/`，执行后自动清理（含 `.uid`、日志、报告）；
3. 上游 `Test/`、`.remap`、探针场景与脚本不进入 `source/`；
4. 迁移中的临时探针只作为可执行规格，验收后移除或在 `scripts/` 中等价重写；
5. 生产源码中不保留 `TODO probe`、临时调试场景或硬编码测试入口；
6. 探针失败必须作为验收失败处理，不能“只记录不阻断”。

## 后果

- 生产工程保持干净，导出包不包含测试资产；
- 测试规格与业务代码分离，但需要维护两套接口同步；
- 临时夹具的生成/清理逻辑本身需要测试；
- 迁移时不能直接复用上游测试文件，必须按当前接口重写。

## 备选方案

| 方案 | 未采用原因 |
|:---|:---|
| 把探针放入 `source/` 长期保留 | 污染生产工程与导出包 |
| 直接复制上游 `Test/` | 依赖旧接口/旧场景，无法维护 |
| 只做手工测试 | 无法回归，证据不可重复 |
