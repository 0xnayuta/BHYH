# ADR-021：Godot 原生场景组合与项目总体目标架构

- **状态**：Accepted（目标契约；不表示运行时重构已完成）
- **记录日期**：2026-10-27
- **关联**：ADR-003、ADR-005、ADR-006、ADR-007、ADR-008、ADR-015、ADR-017、ADR-018、ADR-020
- **局部替代**：替代 ADR-017 决策 §5 将全局视图交换作为长期接入方式的选择；只改变目标方向，当前代码与保存互斥保护继续有效，直到完整迁移验收。其余 ADR 不替代，ADR-020 继续作为视觉子契约。

## 背景

Phase 13 已完成视觉资产契约收口。原 `target_architecture_contract.md` 仅覆盖视觉构建、资源与运行时，不能指导应用编排、档案会话、本地双人、持久化、战斗、关卡和 UI 的后续治理。已有规划还把永久 Global facade、全目录迁移和按文件名判断二进制场景混作现代化目标。

用户要求将该文档提升为项目总体架构目标，并同步修正活跃文档与后续路线。当前工程仍有已验收玩法、存档与双人共享规则，不能用目标架构反向宣称实现完成。

## 决策

1. 采用 Godot 原生场景组合的模块化架构，以业务职责、单一状态写入者和作用域生命周期为主轴；不另建引擎抽象、万能 Manager 或通用服务定位器。
2. 区分应用、档案会话、玩家槽位、关卡、实体、UI 与共享内容定义；由上层装配实际需要的依赖，不向所有对象注入全能上下文。
3. 静态配置优先强类型 Resource；实例状态与 JSON 持久化边界分离。存档不因 Resource 优先而整体改为 `.tres`，共享资源不承载实例可变状态。
4. Global 治理按职责闭环迁移调用方并删除过时入口；名称和职责仍正确的唯一正式入口可保留，不以 facade 为由保留旧 API/双实现。
5. 保留本地双人的个体/共享业务语义、当前存档可靠性策略、既有战斗/关卡规则和显示基线；以显式操作者绑定替代 ADR-017 §5 的长期全局视图交换方向，迁移必须联动保存快照、共享账本与全部受影响面板，不先移除现有保护。
6. 继续执行 ADR-008：保留类型分层顶层，功能子目录与清晰 API 优先。全目录搬迁不是架构完成条件；场景格式需按资源内容取证，不从 `*bundled*` 文件名推断。
7. ADR-020 继续作为视觉资源子契约。总体架构扩展不重开 Phase 13，不新增回退，也不改变已登记例外的事实状态。
8. 路线按真实依赖与风险分批：当前 AtlasMetadata 类型化仍是有限候选；应用/会话/持久化与玩法/UI 有各自工作流，平台验收独立，不强制串行等待目录迁移。
9. 目标规则、实际实现、验证事实、阶段计划分别归目标契约、architecture、status、roadmap/current-iteration；只有实施并验收后才能更新为完成。

## 后果

总体契约扩展为项目级设计与验收入口；Godot 设计、命名、持久化、本地双人与视觉约束具有统一边界。后续工作需要验证共享/隔离、失败传播、异步退出、场景交接和生产调用方迁移，而不只检查类型或目录。

本次只修订文档，不修改运行时代码、不升级内容版本、不承诺额外平台，也不为尚未创建的类型、服务或门禁声称已实现。

## 备选方案

- 维持仅视觉契约：无法约束后续全局/会话/玩法治理，不采用。
- 一次性重写为 ECS 或完全引擎无关分层：缺少本项目收益证据，扩大行为风险，不采用。
- 全部状态改成 Resource、全部功能改成 Autoload：混淆共享配置与可变状态，不采用。
- 先搬完所有目录再做职责拆分：违反现有目录决策，收益无法由路径变化证明，不采用。
